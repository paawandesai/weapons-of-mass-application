## Not verified, and why

1. **Live agent loop on seeded jobs** (task 9.1): trigger a run, watch the run view, cards land in Applied, the simulated recruiter proposes times, confirm from the demo inbox, card reaches Interviewing. Every piece is unit and integration tested, but the full loop was not run live: the Claude Code permission classifier refused the command as a real-world transaction. To run it yourself from the repo root (ports chosen because 3000 and 5173 are in use by other projects on this machine):

   ```bash
   scripts/demo-rehearsal.sh --keep --api-port 3911 --forms-port 4310 --web-port 5174
   ```

   Then, with `DEMO_LOGIN_TOKEN` from `.env`:

   ```bash
   curl -c /tmp/wma.cookies -H "x-demo-token: $DEMO_LOGIN_TOKEN" -X POST http://127.0.0.1:3911/auth/demo
   ```

   ```bash
   curl -b /tmp/wma.cookies -X POST http://127.0.0.1:3911/api/runs
   ```

   Open http://localhost:5174/runs to watch, then /board, then /demo/inbox for the slot-confirmation email. `docs/DEMO.md` has the full walkthrough. Note: the rehearsal's `--scenarios` seed occupies today's run date; for the live loop use the plain seed (`pnpm seed:demo`) on a fresh database.

2. **Real Google sign-in**: the OAuth client exists and the flow is tested against a mocked Google, but nobody has clicked through the consent screen. Sign in at the web app with your own Gmail (listed as the test user) to verify.

3. **CAPTCHA on real vendor forms**: the detector handles text-and-image widgets, which the fixtures use. Real vendors use iframe challenges, so on a live form the chain goes straight to the human stage. That matches the PRD's acceptance criterion but is worth knowing before a demo on a real posting.

## Decisions taken overnight (deviations from the OpenSpec designs)

- No second Gmail account for the simulated recruiter: demo tenants use a local mailbox and calendar behind the same ports the real Gmail and Calendar code uses (wave 4 brief, rule 12).
- A non-production demo sign-in gated by `DEMO_LOGIN_TOKEN`, because the fictional persona has no Google account (rule 13).
- Follow-on work (prep plan after booking, negotiation after offer, mail sync after simulated delivery) goes through a `pending_jobs` outbox written inside the parent transaction and dispatched by a reconciler, instead of enqueue-after-commit.
- Every outgoing email writes a pending delivery receipt before Gmail is called, so an uncertain send reconciles instead of repeating.
- Tests cannot reach the internet: a socket-level guard fails any test that tries.
