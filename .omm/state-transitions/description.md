The application status machine (`ApplicationStatus` in `packages/shared/src/jobs.ts`). Two actors move a card. The agent moves it forward only: the submission job sets `applied` or leaves `pending` with a reason, and mail sync applies `nextStatus` (`packages/shared/src/status.ts`): confirmation promotes `pending` to `applied`, interview promotes `applied` to `interviewing`, offer promotes `applied` or `interviewing` to `offer`, rejection closes anything, `other` changes nothing. The user may move a card anywhere on the board through `POST /api/applications/:id/stage`, which records a `stage_overrides` row and only applies when the status still equals the one the client saw (409 otherwise). `closed` is a sink: the agent never reopens it, every agent write is conditional on the current status, and jobs check `isActionable` first and log `skipped_not_actionable`.
