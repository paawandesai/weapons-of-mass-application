Who enqueues what. pg-boss is the only broker; the worker is the only consumer and the only scheduler. Three kinds of producer: the API (profile build on request, booking and reminders on a confirmed slot, manual runs), the worker's own cron ticks (hourly tick jobs that fan out one job per eligible user, a nightly cleanup, an hourly follow-up repair, the demo recruiter timer), and the `pending_jobs` outbox for follow-on work that must not be lost between a commit and an enqueue. Every queue that can receive duplicates is `exclusive` with a singleton key (user and date for a run, application id for a submission, interview id for a plan), so a second send while one is queued or running returns null instead of a second job.
